# Hop Village: architecture and implementation plan

HopQuest 2.0 adds **Hop Village**, a walkable pixel-art overworld. The child walks and hops their buddy between buildings that open the game's existing modes. This document is the Phase A audit and the plan the code follows.

Branch: `feature/hop-village`

## 2. Presentation choice

The world is a **top-down, three-quarter view** (the classic cozy-RPG camera), not true isometric. Reasons:

- Young kids tap where they want to go. On a square grid the tap lands on the tile they see; isometric diamonds make that harder.
- Collision and pathfinding run on the same grid that's drawn, so movement is deterministic and easy to test.
- Tall sprites (trees, buildings, buddies) are depth-sorted by their foot line. That gives the layered "walk behind the castle" look without isometric math.

Logical tiles are 16 art pixels, drawn at a whole-number scale (3×, so a tile is 48 pt). Everything uses nearest-neighbor filtering, so pixels stay crisp and the same size everywhere.

## 5. Systems

- **Movement.** A fixed 60 Hz step runs inside `update(_:)`. The player is a circle (radius 0.3 tile) that moves against the collision grid one axis at a time, so it slides along walls. Joystick input sets a velocity. A tap runs A* (4-way, octile-smoothed) to the tapped tile, or to the nearest walkable tile next to a tapped building or NPC, then follows the waypoints.
- **Hopping.** Buddies move in little hops: the sprite plays a walk cycle while its art node follows a hop arc, and dust puffs appear at each landing.
- **Interaction.** Each frame, `InteractionFinder` picks the closest NPC within 1.4 tiles, the door the player is standing at, or a portal. The HUD's big button changes to "Talk to Ollie", "Go in", or "Hop in!". Talking freezes the NPC in its Talk state, facing the player.
- **NPCs.** `NPCBrain` is a deterministic state machine (seeded random): Idle → Wander (A* inside a home radius) → Approach (greets a nearby player once) → Talk → Perform activity (at a scheduled spot) → Return home. The first vertical slice ships Ollie Owl. Phase F adds four more buddies.
- **Dialogue.** Lines are curated and written in code. A choice can open a Brain Gate. `QuizCard` records the answer as usual, and the first solve for each NPC gives 1 star, once ever: no repeats, no daily resets.
- **Depth.** Every tall node gets `zPosition = 1000 - footY / tile`, so things lower on the screen draw in front.
- **Camera.** It follows with critical damping and is clamped so the map edge never shows.
- **Environment.** Water and fountain tiles are animated. Butterflies, falling leaves, cloud shadows, and fireflies plus a soft night tint (from the device clock) are added. Two quality levels, Full and Light, are set in the Grown-ups area.
- **Culling.** Props and NPCs farther than one screen from the camera are hidden. The tile map is a single `SKTileMapNode`, so SpriteKit culls it.

## 6. Routing and returning

- New `Route.village`. `RootView` keeps `homeIsVillage`. Every "back" and every balloon landing uses `goHome()`, which returns to the village when the child came from it, or to the map otherwise.
- Chapter completion still runs through `finish(_:stars:)` → `complete` → balloon. The village only decides where the balloon lands.
- Before leaving through a door or portal, the player's tile is saved. Coming back spawns them on that approach tile, facing south.

## 7. Save data

`PlayerProfile.village: VillageSaveState` is decoded with `decodeIfPresent`. A missing block gives a safe default (spawn in the Square). The block contains:

- `version`
- `tileX`, `tileY`, `facing`
- `visited`, `talkedTo`, `solved` (sets of ids)
- `effects` (full / light)
- `startInVillage`

Unlocked locations come from the existing chapter progress and are never stored twice. No existing field is touched.

## 8. Testing

`Tests/VillageLogic/run.sh` compiles the pure village files plus a test file with `swiftc`, on macOS or Linux, and runs it. It checks:

- The map parses to 40×48, and every door, portal and NPC home is reachable from spawn.
- The A* path never crosses a blocked tile, and returns nil for unreachable targets.
- Collision never puts the player circle inside a blocked tile, even when pushed at walls for 10 seconds.
- `NPCBrain` stays inside its wander radius, always returns home, and gives the same results for the same seed.
- `VillageSaveState` decodes from `{}` and from v1 JSON, and round-trips.
- The interaction finder picks the nearest valid target.

Building and running the full app happens in Xcode.

## 9. Child safety

There is no network, no chat, no free text, no accounts, no ads and no streaks. All dialogue is fixed and age-appropriate. Wrong answers just get a hint, as before. The daily limit, break reminders and parent gate cover the village too.

## v2.1 additions

### Main menu and routing
- New `Route.menu` is now the start screen (`MainMenuView`). PLAY opens the village; every game has a tile.
- `RootView` tracks a `Hub` (menu, map or village). Back buttons and balloon landings return to it.
- `openCastle()` keeps My Castle locked until all challenges are done.

### Map v2 (44×54)
- Every game has a building, and every building opens its existing screen:
  - `G` Meadow Street cottage, `D` Driving School, `W` Robot Lab, `V` Lily River boathouse, `X` City Rally garage, `H` Castle Hill tower (story chapters 1–6)
  - `Y` Fort Friends, `A` Pillow Bop, `K` Bubble Kart, `M` Sticker Book, `U` Together clubhouse, `C` castle
- The forest portals are gone. Saves from the first village (version 1) start again in the square.

### Challenges (`Models/VillageChallenges.swift`)
- `VillageChallenge` has nine cases: chapters 1–6 plus Fort, Bop and Kart.
- "Done" is read from the existing save: `completedChapters`, `fortBest`, `bopBest`, `kartBest`.
- `GameStore.castleOpen` is true when all nine are done.

### Pop-quiz buddy (`QuizCourier` in `Models/VillageNPC.swift`)
- A deterministic state machine: waiting → approaching → asking → leaving.
- Its clock only advances while the village is not frozen. It spawns 4–9 tiles away and walks to the player with A*.
- Questions come from `FollowUpBank`. Bonus stars are capped through `VillageSaveState.grantBonus`.

### Live play (`Network/`)
- **Transports:** `VillageTransport` is a protocol with two implementations:
  - `NearbyTransport` (MultipeerConnectivity): encrypted, peer names are random codes, at most 7 peers.
  - `GameCenterTransport` (GameKit): friends picker or automatch; respects `isMultiplayerGamingRestricted`.
- **Messages:** `VillageNetMessage` (`Models/BrainDuel.swift`) is the only thing phones send. `decode` validates every message:
  - size limit
  - known buddies only
  - positions clamped to the map
  - nicknames cleaned to 12 letters, numbers and spaces
  - duel questions checked
- **Duels:** `BrainDuel` scores 10 per correct answer plus up to 5 for speed. Stars are winner 2, tie or good try 1, capped per day.
- **Remote players:** `RemotePeer` smooths their positions and snaps on big jumps. Peers that go silent for 12 s are dropped.
- **Setup:** `Package.swift` declares the Local Network capability with the Bonjour types `_hopq-village._tcp/_udp`.
- **Game Center:** it needs the Game Center entitlement, which Swift Playgrounds app packages can't add. Until the project moves to an Xcode project, the Game Center modes show a "not set up yet" message.

### Tests
- `Tests/VillageLogic/run.sh` now also covers:
  - challenges
  - the courier: timing, pausing, reaching players anywhere
  - the follow-up bank
  - daily caps
  - duel scoring, ties and anti-cheat
  - message validation
  - remote smoothing
- Total: 149,703 checks.

## v2.3 additions

### Coding Lab (`Models/CodeLab/`, `Views/CodeLab/`)
- `CodeCurriculum` holds 15 lessons in three tracks (web, python, games), five each. A lesson has learn cards (read aloud), code lines with blanks (`[[slot]]`), a quick check question and a fun fact.
- Each track builds one growing `CodeProject`. Choices go in `CodeLabSave.values`, so the project keeps what the child built and can be remixed later.
- `MiniPython` is a small, safe Python-subset interpreter: print, numbers, strings, comparisons, `for … in range`, `if/elif/else`, `def`/`return`. It has step, output and size limits and kid-friendly errors with line numbers. There is no file, network or `import` access.
- `GameProgram` runs the Game Maker code with host functions (`set_background`, `add_player`, `add_star`, `jump`, `say`) and the events `on_tap()` and `on_star()`. `CodeGameScene` plays the result.
- Web pages render in a `WKWebView` with JavaScript off and all navigation blocked.
- Lessons: learn → build (fill the blanks, ▶ Run) → check → done (+2 stars the first time).

### Missions (`Models/Missions.swift`)
- Steps: collect items placed in the world, talk to villagers, or finish Coding Lab lessons. `MissionSave` tracks the stage; turn-in pays stars once.
- Seven missions from six new villagers (Kip, Fizz, Ocho, Flora, Polly, Buzzy) and Iron Acorn. A 📜 button shows the mission log.

### World
- Coding Lab building `P` (doorstep (11,27)). Lily pads on row 49 for Fizz's mission. The Hop button can cross water when it lands on a walkable tile.
- Ten challenges now; the tenth is finishing any Coding Lab lesson.

### Tests
- `Tests/VillageLogic/run.sh`: 322,866 checks (adds mission reachability, lily-pad hops, new NPCs).
- `Tests/CodeLab/run.sh`: 214 checks (interpreter, curriculum, every project at every lesson, HTML balance, highlighting, saves).

## v2.6 additions: a living village

### Seasons, weather and festivals (`Models/VillageLife.swift`)
- `Season.of(month:)` uses the device date (northern-hemisphere months). `Weather.on(year:month:day:)` is worked out from the date with `VillageRandom`, so the same day always has the same weather, with nothing downloaded. Snow only falls in winter.
- `Festival`: seven festivals, two per season, alternating by week of the year. The child can pick any festival on the notice board (`VillageSaveState.festivalPick`), so nothing is ever missed.
- `FestivalMissions`: one mission per festival, all hosted by Gemma Giraffe (`gemma`, a new villager). `MissionCatalog.offer(from:save:festival:)` gives the host's festival in progress first, then the one being celebrated. `MissionCatalog.visible` keeps the mission log tidy.
- `VillageStories`: a season line for every villager, plus weather lines, taking turns in chatter.

### Your house (`BuildingKind.home`, footprint `J` at cols 26–30, rows 4–7)
- `HomeStyle` (inside `VillageSaveState.home`): wall, roof and door colors and a set of `HomeExtra` decorations. Four decorations are open from the start; each festival unlocks one more, once.
- Art is drawn in layers by `make_village.py` (`home_wall_*`, `home_roof_*`, `home_door_*`, `home_extra_*`). The scene stacks them as one sprite (`HopVillageScene.updateHome`) and the house redraws live as the child decorates.

### Effects (`VillageEnvironmentSystem`)
- Color washes per season and weather; spring petals, orange autumn leaves, faster leaves when windy; rain and snow pooled in the visible area.
- Falling effects turn off with Reduce Motion, and "Lighter effects" uses fewer of each.
- Grown-ups can switch seasons off (`VillageSaveState.seasons`): the village is then always a sunny spring day.

### Tests
- `Tests/VillageLogic/run.sh` adds: months → seasons, stable daily weather (snow only in winter), weekly festival rotation, festival missions reachable and hosted, the house on the map and reachable, `HomeStyle` decoding (bad values clamped, unknown decorations skipped), older saves loading, and villager lines rotating. 352,193 checks.
