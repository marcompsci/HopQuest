# HopQuest: Apple compliance report

_Audit date: November 12, 2026 · Version 2.0 (build 3) · branch `feature/hop-village` · replaces the October 17, 2026 report_

_Sources of truth:_
- [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), including the October 2026 revision. That revision changed:
  - 1.2: nonconsensual intimate imagery, including AI-generated.
  - New 2.5.19: no changing an app's behavior after review without disclosure.
  - Section 5: trafficking and child exploitation.
- The June 2026 4.2 wording on low-quality and copycat apps.
- Apple's [privacy manifest documentation](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files) and its [required-reason API list](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).

Nothing here guarantees Apple's approval; App Review decides.

## 4. Functionality and crash prevention

- **Static review:**
  - No `try!`.
  - The only `fatalError` is an unused `init(coder:)`.
  - Saved data decodes with defaults (tolerant `init(from:)`), including Star Hop, Level Maker and Brain Bubble in the App Group store.
- **Navigation:** the v9.10 tab bar gives Adventures, Games, Learn and Worlds their own pages. Every page returns to Home, and the tab is remembered.
- **Deep link:** `hopquest://quickgame` does nothing without a player or during rest time. Unknown hosts are ignored.
- **Bedtime / daily limit:** the goodnight screen clears itself in the morning, using the ticker and the foreground event.
- **Not verifiable here:**
  - cold and warm start timing
  - memory (Instruments)
  - iPad rotation on a device
  - VoiceOver walk-through
  - widgets on the Lock Screen
  These are in the checklist.

## 6. Remaining manual Apple Developer actions

1. Approve the merge `feature/hop-village` → `main` (F-3).
2. In Xcode:
   1. Set the destination to Any iOS Device.
   2. Product → Archive.
   3. In the Organizer, run **Validate App**.
   4. Run **Generate Privacy Report**. It should list the app and the widget, with only UserDefaults and system boot time.
3. Upload only when you decide to. Then record the build in `release/last_uploaded.json` (F-9).
4. In App Store Connect:
   - new screenshots (F-4)
   - What's New and What to Test from the docs (F-20)
   - the age rating questionnaire (F-21)
   - Kids Category 6–8
   - privacy label "Data Not Collected"
   - review notes
5. Check the Paid Apps Agreement (F-10).
6. Never press "Submit for Review" or "Add for Review" without the owner's go-ahead.

## 8. Permanent release gate

Before every TestFlight upload:

1. Run `bash scripts/run_tests.sh` and `python3 scripts/release_check.py`. Neither may show a FAIL.
2. The GitHub Actions "Release gate" run must be green for the exact commit you archive. A red or skipped job means not ready.
3. Work through `docs/testflight-release-checklist.md`.
4. When you add a target, framework, permission, SDK, network call, link, purchase or social feature, extend `scripts/release_check.py` in the same change. If the new target calls a required-reason API, it also needs its own `PrivacyInfo.xcprivacy`.
